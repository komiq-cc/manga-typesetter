# Text-port verification harness

The app is moving its text measurement and drawing from browser APIs to a Rust
engine. This harness is how every step of that move is checked: it runs one
fixed corpus through a text engine, stores what the app measured, laid out and
painted, and compares two such runs.

It always goes through the app's own public functions (`measure.js`,
`contain.js`, `exporter.js`), never around them, so the same harness runs
unchanged before the port, during it and after it. What it records is what the
app believes and what the app paints.

This file is the contract between the parts. Change the contract here first.

## Engines

| id | What runs the app's code |
|---|---|
| `ref-sk` | node + `@napi-rs/canvas` (Skia), the existing `realfont` vitest lane |
| `ref-cr` | Chromium, the Vite dev server opened in a browser |
| `ref-wk` | the Tauri dev app's own webview (WKWebView on macOS) |
| `ref-hb` | real HarfBuzz (`harfbuzzjs`); shaping records only |
| `new` | the Rust engine (wasm) |

## Data directory

Everything the harness reads or writes that is not source code lives under
`$TP_DATA` (default `node_modules/.cache/text-port`). Nothing under it is
committed: it holds the user's fonts and chapter text.

```
$TP_DATA/
  fonts/fonts.json            the font list (below)
  fonts/<sha256>.<ext>        font files, named by content
  corpus/metrics.json         C1
  corpus/layout.json          C2
  corpus/pixels.json          C3
  runs/<engine>/<runId>/      one capture
    manifest.json
    metrics.jsonl
    layout.jsonl
    pixels.jsonl
    png/<caseId>.png
  reports/<name>/             one comparison
    report.json
    report.html
    img/...
```

`runId` is `YYYYMMDD-HHMMSS` in UTC unless given.

## fonts.json

```json
{ "version": 1,
  "fonts": [
    { "family": "Comic Neue", "slot": "regular",
      "file": "<sha256>.ttf", "sha256": "<hex>", "source": "src/test/fonts/ComicNeue-Regular.ttf" }
  ] }
```

- `family` is the name a box's `style.font` uses.
- `slot` is one of `regular`, `bold`, `italic`, `boldItalic` (`FACE_SLOTS` in
  `src/lib/fonts.js`).
- Every host registers exactly these files under these names before it
  measures. A family in the corpus that is not in `fonts.json` is an error, not
  a fallback: a run must never silently measure a substitute face.

## Corpus

Built once by `scripts/text-port/build-corpus.mjs` and then frozen; every engine
reads the same three files. Case ids are stable strings, unique within a file,
safe as file names (`[a-z0-9._-]`).

`metrics.json`

```json
{ "version": 1, "cases": [
  { "id": "m.comic-neue.r.22.kern-av", "font": "Comic Neue",
    "bold": false, "italic": false, "size": 22, "text": "AVATAR WAVE" } ] }
```

`layout.json` and `pixels.json`

```json
{ "version": 1, "cases": [
  { "id": "l.oval-short.smart", "mode": "smart",
    "page": { "w": 800, "h": 1200 },
    "box": { "id": 1, "x": 100, "y": 100, "w": 240, "h": 120,
             "text": "...", "style": { }, "fit": null } } ] }
```

- `mode` is the chapter typesetting mode, `smart` or `plain`.
- `box.style` is a complete style as `defaultStyle()` in `src/lib/data.js`
  makes it, with the case's overrides applied by the corpus builder, so no host
  fills in defaults of its own.
- A case may carry `"tags": ["kern", "faux-bold", ...]` for grouping in reports.

A layout case may instead carry `"solve": { ... }`, the arguments of one
`solveLayout` call (`src/lib/auto-layout.js`); its record is the solver's
answer. A pixels case carries `"via": "texture"` (the default,
`renderBoxTexture`) or `"via": "layer"` (`renderBoxLayer`, the page-space paint
that rotation, flips and the direct route go through).

Sources of cases:

1. Synthetic, generated by code in `src/test/text-port/corpus.js`. Deterministic,
   no randomness without a fixed seed.
2. Real chapters, read from copies under `$TP_DATA/chapters/` only.

The lettering bench (`scripts/typeset-bench.mjs`) stays its own run with its own
`report.json`; it is compared as a file, not folded into the corpus.

## What a capture records

One JSON object per line. Numbers are written as the engine returned them, no
rounding. A case that cannot run on a host is still written, with
`"skip": "<reason>"`; a missing line means the capture is broken.

`metrics.jsonl`, one line per case:

```json
{ "id": "...",
  "adv": 123.456,
  "chars": [10.1, 9.8],
  "font": { "ascent": 20.9, "descent": 5.6 },
  "ink": { },
  "glyphs": { "A": { } } }
```

| field | from |
|---|---|
| `adv` | `lineWidth(text, style, size)` with `letterSpacing: 0` |
| `chars` | `charWidths(text, style, size)` |
| `font` | `fontMetrics(style, size)` |
| `ink` | `lineInk(text, style, size)`, every field it returns |
| `glyphs` | `glyphInk(ch, style, size)` for each distinct code point of `text`, at most 24 |

`layout.jsonl`, one line per case, from `placeBlock(boxCandidate(box, text))`,
`boxInkRect` and `containBox`:

```json
{ "id": "...", "lines": ["..."], "lineX": [0], "blockY": 0, "blockH": 0,
  "baseY": 0, "lineH": 0, "curve": null,
  "ink": { "l": 0, "t": 0, "r": 0, "b": 0 }, "verdict": { } }
```

`curve` is the glyph record array (`ch, x, y, rot, w`) for arc, circle and path
text, else `null`. A `solve` case records
`{ "id": "...", "solve": { "size", "x", "y", "w", "h", "lines", "status", "reason" } }`.

`pixels.jsonl`, one line per case, from `renderBoxTexture(box, page)`:

```json
{ "id": "...", "png": "png/<id>.png", "ox": 0, "oy": 0, "cw": 0, "ch": 0, "ss": 2,
  "bbox": [0, 0, 0, 0], "alphaSum": 0 }
```

The PNG is the texture canvas exactly as the exporter made it (device pixels,
transparent background). For `"via": "layer"` the PNG is the cropped layer and
the record carries `"left"` and `"top"` (page px) in place of `ox`/`oy`, with
`"ss": 1`. `bbox` is `[left, top, right, bottom]` of `alpha > 0`
in device pixels, right and bottom exclusive, or `null` for an empty texture.

`manifest.json`

```json
{ "engine": "ref-sk", "runId": "...", "commit": "<git sha>", "dirty": false,
  "host": { "userAgent": "...", "platform": "...", "dpr": 1 },
  "corpus": { "metrics": "<sha256>", "layout": "<sha256>", "pixels": "<sha256>" },
  "fonts": "<sha256 of fonts.json>",
  "counts": { "metrics": 0, "layout": 0, "pixels": 0, "skipped": 0 },
  "startedAt": "...", "finishedAt": "..." }
```

## Parts

| Path | Job |
|---|---|
| `src/test/text-port/corpus.js` | builds the synthetic cases; pure, runs anywhere |
| `src/test/text-port/probe.js` | runs corpus cases through the app's functions and yields records; pure, takes the app modules as an argument, no file or network access |
| `src/lib/text-port-capture.realfont.test.js` | node host (`ref-sk`): registers the fonts with `@napi-rs/canvas`, runs the probe, writes the run. Does nothing unless `TP_CAPTURE=1` |
| `scripts/text-port/capture-node.mjs` | launches that lane with the right environment |
| `capture.html` + `src/test/text-port/host-browser.js` | browser host (`ref-cr`, `ref-wk`): a dev-only page that loads the fonts and corpus from the collector, runs the probe, posts the records back |
| `scripts/text-port/collector.mjs` | local HTTP server on `127.0.0.1`: serves `fonts/` and `corpus/` from `$TP_DATA`, accepts the run's files |
| `scripts/text-port/build-corpus.mjs` | writes `fonts.json` and the three corpus files |
| `scripts/text-port/compare.mjs` | compares two runs, writes `report.json` and `report.html`, exits non-zero when a gate fails |
| `scripts/text-port/gates.json` | the thresholds |

## Comparing

`node scripts/text-port/compare.mjs <runA> <runB> [--out <dir>] [--gates <file>]`

`runA` is the reference ("before"), `runB` the candidate ("after"). Cases are
joined by `id`; a case present in one run only is reported and fails the run.

Numbers (`metrics.jsonl`): per field, the absolute and relative difference;
per font and per field: count, max, median, 99th percentile, and the 200 worst
cases.

Decisions (`layout.jsonl`): per case, whether `lines` are identical; the largest
difference in `lineX`, `blockY`, `baseY`, `ink`; whether the verdict changed.

Pictures (`png/`), per case, on the alpha channel:

- `bboxDelta`: largest edge difference between the two `bbox`es, device px.
- `iou`: overlap of the two `alpha >= 128` masks.
- `meanAbs`: mean absolute alpha difference over the union of both `alpha > 0`.
- `thick`: the thickness of the widest part of the disagreement region, device
  px: twice the largest value of the distance transform of the XOR of the two
  `alpha >= 128` masks. Antialiasing differences are thin; a wrong glyph, a
  wrong kern or a wrong stroke width is thick.
- images for the report: before, after, and a difference heat map.

The textures of the two runs may differ in size and origin. They are aligned by
their `ox`/`oy` (the box's top-left corner inside the texture) before any
pixel is compared.

`report.html` is one self-contained page (plain HTML, CSS and a little script,
no dependency, images by relative path): a summary of each gate, the tables
above, and per-case rows with before, after, heat map and a flicker toggle,
worst first.

## Rules

- A capture is repeatable: two runs of the same engine on the same commit give
  byte-identical `metrics.jsonl`, `layout.jsonl` and PNGs.
- No host invents a number. No silent skip, no silent fallback font.
- Real chapters are only ever read from copies under `$TP_DATA/chapters/`.
- Nothing under `$TP_DATA` is committed.
